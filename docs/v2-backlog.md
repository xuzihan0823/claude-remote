# 第二版本待做清单

建立日期：2026-11-06。基于 `main` 的 `8179247` 及本轮 Claude Code 能力盘点，记录后续接入范围。本文件是产品待做清单，不代表功能已经实现，也不承诺交付日期；各项实施进度和验证结果记录在对应 PR 中。

盘点依据是当前源码、项目安装的 Agent SDK `0.3.212` 和官方文档。本机 `claude --version` 为 `2.1.309`，但 daemon 可通过 `CLAUDE_BIN` 使用另一套 CLI；SDK 类型存在不等于实际运行的 CLI 已验证支持。实施时按实际版本和协议能力确认，不盲目升级依赖。

## 已有基础

目前已有新建与续聊、主会话流式回复、停止运行、模型与思考强度选择、权限模式、基本规划审批、选择与自由回答问题、任意文件上传，以及输出文件预览与保存。这些不重复列为待实现。

本机已配置的 Skills、MCP、插件、规则和 hooks 可随 CLI/SDK 配置继承。手输非交互命令也有输入通路；缺少手机入口或完整回显，不应写成底层完全不支持。具体命令和工具仍需在实际 CLI 上验证。

## P1：日常对话与信息展示

- [ ] **V2-01 命令与 Skills 的发现、调用和回显**

  现状：输入文本直接进入 SDK，但手机没有可用命令列表或补全；桥接层丢弃 `local_command_output`、命令列表及其更新事件，转录解析也会剥离命令输出标签。

  验收：按当前会话展示可用命令和技能，支持查找与填入参数；命令输出可读、可恢复，不出现“执行了却没有结果”。按 SDK 实际公布的能力展示，不把需要终端交互的命令一律当作可用。

- [ ] **V2-02 运行中补充指令与消息排队**

  现状：底层 `steer()` 已存在，但手机发送条件和后台运行锁拒绝活跃轮次中的新消息；目前只能编辑草稿，停止后再发送。

  验收：可在生成或工具执行期间发送补充要求，明确区分已排队、已送达及已处理；停止、重连、重复请求和切换会话不造成重复执行或消息错投，保留现有停止能力。

- [ ] **V2-03 上下文用量与手动压缩**

  现状：原生自动压缩和手输 `/compact` 的输入通路保留，但未接上下文查询、压缩状态及 `compact_boundary` 结果。

  验收：可查看上下文占用与组成、手动发起压缩并传入重点说明；压缩中、成功、失败或无需压缩均有明确结果，重连后不会重复压缩。

- [ ] **V2-04 Token、费用和适用的额度信息**

  现状：SDK 结果包含 `usage`、`modelUsage`、`total_cost_usd` 等字段，事件适配时未保留。

  验收：可查看本轮和会话的 Token 用量、模型用量与费用估算，明确统计范围，避免累计时重复计数；订阅额度仅在认证方式支持时展示，缺失时不伪造。SDK 费用估算与第三方网关实际账单分别标明；不依赖未稳定的实验接口作唯一数据源。

## P2：任务、会话与扩展管理

- [ ] **V2-05 子代理与后台任务的状态和控制**

  现状：主链的 Agent、Bash 等工具卡可显示，但子代理流被跳过，任务开始、进度、结束及后台任务集合事件未接，也没有独立任务停止接口。

  验收：能区分任务与普通工具调用，查看运行状态、进度、耗时、摘要及可用的子代理输出，并单独停止任务；事件去重、乱序、重连和结束状态可正确对账。跨轮持续运行依赖 V2-11，不能用普通工具卡代替生命周期管理。

- [ ] **V2-06 会话分支与改名**

  现状：SDK 支持分支和改名，但手机无显式入口；当前会话标题索引没有完整读取原生自定义标题。

  验收：支持改名并在刷新、重启后正确显示；可复制当前历史另开会话，保留原会话并正确关联新 ID。分支只复制会话历史，不自动隔离项目文件；如需并行修改，另行明确工作目录或 worktree 策略。

- [ ] **V2-07 检查点、文件撤销与对话回退**

  现状：未启用 SDK 文件检查点，也未开放 `rewindFiles()` 等控制。

  验收：先明确“只恢复文件”“只回退对话”“同时恢复”的支持范围，分别验证官方接口；可预览目标检查点和受影响文件，确认后执行，缺失检查点时明确拒绝。SDK 文件回退本身不回退对话，也不能保证恢复所有 Bash 或子代理改动，不能宣称为完整项目回滚。历史变动后正确刷新手机会话。

- [ ] **V2-08 MCP 与插件的状态、管理和交互**

  现状：本机配置可继承，但未开放连接状态、重连、启停和重载控制；也未接 `onElicitation`，MCP 额外的表单或 URL 授权请求缺少手机处理通路。

  验收：可查看实际加载的 MCP 服务和插件，对支持的项目执行重连、启停及重载；支持 MCP 所需的用户输入与授权往返，取消、过期和断线按安全默认处理。先明确配置作用于当前会话还是持久设置，再开放增删与保存。

- [ ] **V2-09 权限规则与规划审批增强**

  现状：已有基本规划模式、允许一次、拒绝理由与问答；未接 SDK 权限规则建议、规则持久化及专门的计划预览和执行选项。

  验收：可查看可用的完整计划内容并作出明确决定；接入 SDK 实际提供的权限建议，选择规则时明确作用范围和保存位置。不把一次允许升级为永久允许；失败、断线和过期仍按现有审批边界拒绝。运行中的权限变更与仅影响下一轮的选择须区分。

- [ ] **V2-10 原生富媒体消息与历史还原**

  现状：手机附件以文件落盘后引用路径；转录解析主要保留文字，原生图片、文档及工具结果中的非文字块没有完整还原。

  验收：对支持的图片和文档消息块保留类型及可用内容，浏览终端历史时也能正确展示或打开；内容缺失、超限和不支持的类型有明确占位。沿用现有文件访问限制，分别处理手机上传与历史原生附件，不把“任意文件可上传”当作所有格式都可被模型理解。

## P3：需要单独设计的运行架构

- [ ] **V2-11 跨轮会话宿主、后台工作与循环任务**

  现状：runner 以首个 `result` 作为一轮终点，随后关闭 SDK Query 和 CLI 子进程；没有跨轮后台工作或 `/loop` 的持续宿主保障。不能据此断言所有脱离父进程的任务都会终止。

  验收：先设计会话进程的存活、空闲回收、资源上限、重连、daemon 重启恢复和显式停止，再支持跨轮后台任务及循环任务。区分手机退后台、手机断线、主机睡眠和主机进程退出，明确哪些情况下继续、暂停或需要恢复；可查看和取消已安排任务，恢复时不重复执行。

- [ ] **V2-12 活跃终端会话的双端实时控制**

  现状：已有同一 JSONL 的只读镜像，以及终端退出后的 SDK 续聊；活跃终端进程通常保持占用。手机审批只来自 daemon 自己启动的 SDK run，不能回答外部终端进程的审批。

  验收：先确认可支持的附着或会话宿主方案，再接入同一进程的双端输入、停止和审批；多客户端操作可对账，不能用解除占用后另起 SDK 冒充附着，也不能删除现有占用保护来绕过冲突。官方 Remote Control 有认证和服务端要求，不直接假定能复用为现有自托管连接协议。

## 实施顺序与约束

先完成 V2-01 的命令回显与必要事件透传，再推进运行中补充消息、上下文及用量；任务管理与长期宿主的设计应协调。分支、改名和检查点涉及会话写入，实施前核对并明确更新现有“daemon 只读 JSONL”的架构契约，不直接手改历史文件绕过 SDK。

优先复用官方 CLI/SDK 能力和现有连接、缓存、审批机制。遇到实际版本不支持时明确标记，不用假数据填补。测试按变更影响选择；涉及消息投递、审批、文件恢复和后台生命周期的项目须验证重连、重复请求及失败路径。

新增或调整手机页面、按钮、入口和文案时，按仓库前端规则先确认具体交互。本清单只记录范围，不授权实施全部界面改动。
